# មេរៀនទី១៖ ការគណនាលើពពក និង Google Earth Engine

!!! info "ព័ត៌មានមេរៀន"
    **រយៈពេលបង្រៀនដែលស្នើ៖ ៣ ម៉ោង** · មេរៀនទី ១ ក្នុងចំណោម ១៥

ក្នុងសៀវភៅទី៣ យើងបានទាញយករូបភាព Landsat មួយផ្ទាំង (ប្រហែល ១ GB) កែតម្រូវវា ហើយចាត់ថ្នាក់វាក្នុង QGIS។ វិធីនោះល្អសម្រាប់រៀនគោលការណ៍ ប៉ុន្តែវាមិនអាចពង្រីកទៅ **ប្រទេសទាំងមូល ក្នុងរយៈពេលដប់ឆ្នាំ** បានទេ៖ ការងារបែបនេះត្រូវការរូបភាពរាប់ម៉ឺនផ្ទាំង និងទិន្នន័យរាប់ TB។

មេរៀននេះណែនាំគំនិតដែលប្ដូរវិធីធ្វើការវិភាគរូបភាពផ្កាយរណបក្នុងទសវត្សរ៍ចុងក្រោយ៖ **នាំកូដទៅកន្លែងទិន្នន័យ ជំនួសការនាំទិន្នន័យមកកុំព្យូទ័រ**។ យើងនឹងស្គាល់ Google Earth Engine ផ្នែកសំខាន់ៗរបស់វា និងសរសេរស្គ្រីបដំបូង។

---

## ១.១. គោលបំណងសិក្សា

បន្ទាប់ពីបញ្ចប់មេរៀន និស្សិតអាច៖

1. ពន្យល់ហេតុផលដែលការវិភាគទ្រង់ទ្រាយធំ ពិបាកធ្វើលើកុំព្យូទ័រផ្ទាល់ខ្លួន។
2. ពិពណ៌នាគំនិត «នាំកូដទៅកន្លែងទិន្នន័យ» និងអត្ថប្រយោជន៍របស់វា។
3. រាយផ្នែកសំខាន់ៗនៃ Google Earth Engine៖ កាតាឡុក ម៉ាស៊ីនគណនា API Code Editor និង Apps។
4. បើក Code Editor សរសេរ និងដំណើរការស្គ្រីបសាមញ្ញ ដែលបង្ហាញរូបភាពលើផែនទី។
5. វាយតម្លៃពេលណាគួរប្រើ Earth Engine និងពេលណាគួរប្រើ QGIS។

### ចំណេះដឹងមុនត្រូវមាន

- សៀវភៅទី៣៖ ក្រុមរលក បន្សំពណ៌ និងកម្រិតដំណើរការ (Level-1 Level-2)។
- សៀវភៅទី២៖ ស្រទាប់វ៉ិចទ័រ និងប្រព័ន្ធកូអរដោនេ។
- គណនី Google និងការចុះឈ្មោះ Earth Engine ([ឧបសម្ព័ន្ធ ក](../appendix/a-gee-setup.md))។

## ១.២. ស្ថានភាពបើកមេរៀន៖ ផែនទីទឹកជំនន់ដប់ឆ្នាំ ក្នុងមួយសប្ដាហ៍

ក្រសួងមួយស្នើឲ្យក្រុមរបស់អ្នកធ្វើផែនទី **ផ្ទៃទឹកអតិបរមាប្រចាំឆ្នាំ នៃបឹងទន្លេសាប ពីឆ្នាំ ២០១៥ ដល់ ២០២៤** ហើយត្រូវប្រគល់ក្នុងមួយសប្ដាហ៍។ តំបន់នេះគ្របលើ tile Sentinel-2 ប្រហែល ៦ ហើយ tile នីមួយៗមានរូបភាពប្រហែល ៧០ ផ្ទាំងក្នុងមួយឆ្នាំ។

អ្នកគណនាលឿនៗ៖ ៦ tile × ៧០ ផ្ទាំង × ១០ ឆ្នាំ = **៤ ២០០ ផ្ទាំង** ហើយនីមួយៗធំប្រហែល ០,៨ GB។ ទិន្នន័យសរុបជាង **៣ TB**។ ដោយអ៊ីនធឺណិត ២០ Mbps ការទាញយកតែមួយមុខ ចំណាយពេលជាងពីរសប្ដាហ៍ ហើយកុំព្យូទ័រយួរដៃរបស់អ្នកមានថាសទំនេរត្រឹម ២០០ GB។

សំណួរដែលមេរៀននេះឆ្លើយ៖

- តើមានវិធីធ្វើការវិភាគនេះ ដោយមិនទាញយកទិន្នន័យ ៣ TB ទេឬ?
- តើការគណនាលើពពក ប្ដូរអ្វីខ្លះ និងមិនប្ដូរអ្វីខ្លះ ក្នុងការងាររបស់អ្នកវិភាគ?
- តើត្រូវចាប់ផ្ដើមសរសេរស្គ្រីប Earth Engine ដំបូងយ៉ាងដូចម្ដេច?

## ១.៣. ទ្រឹស្ដីស្នូល

### ១.៣.១. បញ្ហាទំហំ៖ ហេតុអ្វីកុំព្យូទ័រមួយមិនគ្រប់គ្រាន់

ផ្កាយរណបសង្កេតផែនដីបង្កើតទិន្នន័យរាល់ថ្ងៃ។ Sentinel-2 តែមួយ ផលិតទិន្នន័យជាង ១ TB ក្នុងមួយថ្ងៃ ហើយបណ្ណសារ Landsat បូក Sentinel មានទំហំរាប់សិប petabyte (PB)។ ចំណុចសំខាន់មិនមែនទំហំបណ្ណសារទាំងមូលទេ ប៉ុន្តែជា **ទំហំនៃសំណួររបស់យើង**៖ សំណួរដែលប្រើតំបន់ធំ និងរយៈពេលវែង ត្រូវការរូបភាពរាប់ពាន់ផ្ទាំង សូម្បីតែសម្រាប់ប្រទេសតូចមួយដូចកម្ពុជា។

{{FIG:a01-archive}}

បញ្ហាមានបីកម្រិត៖ **ការផ្ទេរ** (ពេលទាញយក) **ការរក្សាទុក** (ថាសរឹង) និង **ការគណនា** (កុំព្យូទ័រមួយដំណើរការរូបភាពម្ដងមួយៗ)។ បើការងារមួយត្រូវការរូបភាព ៤ ០០០ ផ្ទាំង ហើយផ្ទាំងនីមួយៗប្រើ ៥ នាទីដើម្បីកែតម្រូវ និងគណនា ពេលសរុបគឺ ២០ ០០០ នាទី (ជាង ១៣ ថ្ងៃ) មុនការវិភាគពិតចាប់ផ្ដើម។

### ១.៣.២. គំនិត «នាំកូដទៅកន្លែងទិន្នន័យ»

ដំណោះស្រាយគឺប្ដូរទិសដៅ៖ ជំនួសឲ្យការផ្លាស់ទីទិន្នន័យដ៏ធំ (TB) ទៅកុំព្យូទ័ររបស់យើង យើងផ្ញើ **កូដតូចមួយ** (ពីរបីគីឡូបៃ) ទៅកន្លែងដែលទិន្នន័យស្ថិតនៅ។ ម៉ាស៊ីនមេរាប់ពាន់ ដំណើរការកូដនោះស្របគ្នាលើផ្នែកផ្សេងៗនៃទិន្នន័យ ហើយបញ្ជូនមកយើងវិញតែ **លទ្ធផល**៖ ផែនទីមួយ តារាងមួយ ឬក្រាបមួយ។

{{FIG:a01-workflows}}

គំនិតនេះមិនមែនថ្មីទេក្នុងវិទ្យាសាស្ត្រកុំព្យូទ័រ ប៉ុន្តែវាប្ដូរការងារភូមិព័ត៌មានវិទ្យាយ៉ាងខ្លាំង៖ ការងារដែលធ្លាប់ត្រូវការក្រុមអ្នកជំនាញ និងម៉ាស៊ីនមេផ្ទាល់ខ្លួន ឥឡូវនិស្សិតម្នាក់ធ្វើបានពីកម្មវិធីរុករក។ វាក៏ប្ដូរ **កន្លែងចំណាយពេល**៖ ពីការទាញយក និងរៀបចំឯកសារ ទៅការគិតពីសំណួរ ការសរសេរកូដ និងការផ្ទៀងផ្ទាត់លទ្ធផល។

!!! note "អ្វីដែលមិនប្ដូរ"
    រូបវិទ្យាក្នុងសៀវភៅទី៣ នៅតែពិតដដែល៖ ពពក ស្រមោល មុំព្រះអាទិត្យ ការត្រួតគ្នានៃរូបភាព និងកំហុសចាត់ថ្នាក់ មិនបាត់ទៅវិញទេ ដោយសារយើងគណនាលើពពក។ Earth Engine ធ្វើឲ្យការគណនាលឿន ប៉ុន្តែមិនធ្វើឲ្យការសម្រេចចិត្តខុស ក្លាយជាត្រូវទេ។

### ១.៣.៣. Google Earth Engine មានអ្វីខ្លះ

Google Earth Engine (ហៅកាត់ GEE ឬ Earth Engine) ជាវេទិកាដែល Google បើកដំណើរការតាំងពីឆ្នាំ ២០១០ ហើយឥតគិតថ្លៃសម្រាប់ការសិក្សា ការស្រាវជ្រាវ និងអង្គការមិនរកប្រាក់ចំណេញ។ វាមានផ្នែកសំខាន់ៗប្រាំមួយ៖

| ផ្នែក | តួនាទី | ឧទាហរណ៍ |

| ការនាំចេញ | រក្សាទុកលទ្ធផលជាឯកសារ | GeoTIFF ទៅ Google Drive · CSV |

កាតាឡុកនេះគឺជាអត្ថប្រយោជន៍ធំបំផុតសម្រាប់កម្ពុជា៖ ទិន្នន័យដែលពិបាកទាញយក ឬរៀបចំ ដូចជា ទឹកភ្លៀង CHIRPS (មេរៀនទី៨) ផែនទីការបាត់បង់ព្រៃ Hansen (មេរៀនទី១០) ឬ Sentinel-1 ដែលបានកែតម្រូវរួច (មេរៀនទី៧) អាចប្រើបានភ្លាមៗ។

Code Editor មានបួនតំបន់។ **ខាងឆ្វេង**៖ ផ្ទាំង Scripts (ស្គ្រីបរបស់អ្នក) Docs (ឯកសារ API ដែលប្រាប់មុខងារទាំងអស់) និង Assets (ទិន្នន័យដែលអ្នកផ្ទុកឡើង)។ **កណ្ដាល**៖ កន្លែងសរសេរកូដ ជាមួយប៊ូតុង **Run** **Save** និង **Get Link**។ **ខាងស្ដាំ**៖ Inspector (ចុចលើផែនទីដើម្បីមើលតម្លៃក្រឡា) Console (លទ្ធផលពី `print()` និងសារកំហុស) និង Tasks (ការនាំចេញ)។ **ខាងក្រោម**៖ ផែនទី ដែលបង្ហាញស្រទាប់ពី `Map.addLayer()`។

!!! tip "ចែករំលែកស្គ្រីបដោយតំណ"
    ប៊ូតុង **Get Link** បង្កើតតំណមួយ ដែលអ្នកដទៃបើកបាន ហើយឃើញកូដដូចអ្នកសរសេរ។ នេះងាយស្រួលសម្រាប់ផ្ញើកិច្ចការទៅគ្រូ ឬសួរជំនួយ។ កូដត្រូវបានចែករំលែក ប៉ុន្តែទិន្នន័យផ្ទាល់ខ្លួនក្នុង Assets មិនចែករំលែកដោយស្វ័យប្រវត្តិទេ។

### ១.៣.៥. ស្គ្រីបដំបូង

ស្គ្រីបខាងក្រោមរកមើលរូបភាព Sentinel-2 ដែលមានពពកតិចបំផុតលើភ្នំពេញ ក្នុងរដូវប្រាំងឆ្នាំ ២០២៤ ហើយបង្ហាញវាជាពណ៌ពិត៖

```javascript
// ចំណុចមួយនៅភ្នំពេញ (រយៈបណ្ដោយ រយៈទទឹង)
var pp = ee.Geometry.Point(104.92, 11.55);

// បណ្ណសារ Sentinel-2 Level-2A → ត្រងតាមទីតាំង និងកាលបរិច្ឆេទ
var img = ee.ImageCollection('COPERNICUS/S2_SR_HARMONIZED')
  .filterBounds(pp)
  .filterDate('2024-01-01', '2024-03-31')
  .sort('CLOUDY_PIXEL_PERCENTAGE')   // ពពកតិចបំផុតមុនគេ
  .first();

print('រូបភាពដែលបានជ្រើស', img);    // មើលក្នុង Console
Map.centerObject(pp, 11);
Map.addLayer(img, {bands: ['B4', 'B3', 'B2'], min: 0, max: 3000}, 'ពណ៌ពិត');
```

{{FIG:a01-first-script}}

ចំណាំបីចំណុច៖ (១) យើងមិនបានទាញយកអ្វីទាំងអស់ទេ (២) ពាក្យ `ee.` ប្រាប់ថាវត្ថុនោះរស់នៅលើម៉ាស៊ីនមេរបស់ Google (មេរៀនទី២) និង (៣) ឈ្មោះក្រុមរលក និង `max: 3000` មកពីការយល់ដឹងក្នុងសៀវភៅទី៣៖ Sentinel-2 L2A រក្សាការចាំងផ្លាតគុណនឹង ១០ ០០០។

### ១.៣.៦. ពេលណាប្រើ Earth Engine និងពេលណាប្រើ QGIS

{{FIG:a01-pros-cons}}

Earth Engine មិនជំនួស QGIS ទេ។ វាល្អបំផុតសម្រាប់ការងារដែល **ធំ** (តំបន់ ឬរយៈពេល) ហើយប្រើ **ទិន្នន័យក្នុងកាតាឡុក**។ QGIS នៅតែល្អជាងសម្រាប់ការកែសម្រួលវ៉ិចទ័រ ការគូសព្រំ ការរៀបចំប្លង់ផែនទីបោះពុម្ព និងទិន្នន័យក្នុងស្រុកដែលមិនមាននៅលើអ៊ីនធឺណិត។ លំហូរការងារជាក់ស្ដែងជាទូទៅគឺ៖ **គណនាធំៗក្នុង Earth Engine → នាំចេញលទ្ធផល → បញ្ចប់ក្នុង QGIS**។

| កិច្ចការ | ឧបករណ៍សមស្រប |
|---|---|
| Composite ឥតពពកនៃប្រទេសទាំងមូល | Earth Engine |
| ស៊េរីពេលវេលា NDVI ១០ ឆ្នាំ | Earth Engine |
| គូសព្រំដីធ្លីពីរូបភាពដ្រូន | QGIS |
| ប្លង់ផែនទីបោះពុម្ព A3 | QGIS |
| ស្ថិតិតាមខេត្តពីទិន្នន័យ CHIRPS | Earth Engine → CSV → Excel/QGIS |

!!! warning "លក្ខខណ្ឌប្រើប្រាស់"
    Earth Engine ឥតគិតថ្លៃសម្រាប់ការសិក្សា និងការស្រាវជ្រាវមិនរកប្រាក់ចំណេញ ប៉ុន្តែការប្រើប្រាស់ពាណិជ្ជកម្មត្រូវការអាជ្ញាប័ណ្ណ ហើយគម្រោងនីមួយៗត្រូវភ្ជាប់ជាមួយ Google Cloud Project។ លក្ខខណ្ឌទាំងនេះអាចប្ដូរ៖ ពិនិត្យគេហទំព័រ Earth Engine មុនចាប់ផ្ដើមគម្រោងធំ។

## ១.៤. ឧទាហរណ៍ដែលបានដោះស្រាយ៖ រាប់រូបភាពប្រើការបានលើខេត្តមួយ

មុនចាប់ផ្ដើមគម្រោង អ្នកចង់ដឹងថាមានរូបភាព Sentinel-2 ប៉ុន្មានផ្ទាំង ដែលប្រើការបានលើខេត្តកំពង់ឆ្នាំង ក្នុងឆ្នាំ ២០២៤។

### ជំហានទី១៖ កំណត់តំបន់

ប្រើព្រំរដ្ឋបាលពីកាតាឡុក (FAO GAUL ឬ geoBoundaries) ជំនួសការគូសដោយដៃ៖

```javascript
var prov = ee.FeatureCollection('FAO/GAUL/2015/level1')
  .filter(ee.Filter.eq('ADM1_NAME', 'Kampong Chhnang'));
Map.addLayer(prov, {color: 'red'}, 'ខេត្ត');
```

### ជំហានទី២៖ ត្រង និងរាប់

```javascript
var s2 = ee.ImageCollection('COPERNICUS/S2_SR_HARMONIZED')
  .filterBounds(prov)
  .filterDate('2024-01-01', '2025-01-01');
print('រូបភាពសរុប', s2.size());
print('ពពក < ២០%', s2.filter(ee.Filter.lt('CLOUDY_PIXEL_PERCENTAGE', 20)).size());
```

### ជំហានទី៣៖ បកស្រាយ

ឧបមាថា Console បង្ហាញ ២៩០ និង ៩៥។ មានន័យថា ប្រហែល ៣៣% នៃរូបភាពមានពពកតិច។ រូបភាពមួយក្នុងចំណោម ២៩០ អាចជា tile ពីរត្រួតគ្នាលើថ្ងៃតែមួយ ដូច្នេះ «ចំនួនថ្ងៃ» តិចជាងចំនួនរូបភាព។

### ជំហានទី៤៖ សេចក្ដីសន្និដ្ឋាន

> «សម្រាប់ខេត្តកំពង់ឆ្នាំង ឆ្នាំ ២០២៤ មានរូបភាពពពកតិច (< ២០%) ប្រហែល ៩៥ ផ្ទាំង ភាគច្រើននៅរដូវប្រាំង។ ដូច្នេះ composite រដូវប្រាំងអាចធ្វើបាន ប៉ុន្តែការតាមដានរដូវវស្សាត្រូវការ Sentinel-1។»

!!! warning "អ្វីដែលយើងមិនអាចសន្និដ្ឋាន"
    `CLOUDY_PIXEL_PERCENTAGE` គិតលើ tile ទាំងមូល (១០០ × ១០០ គម) មិនមែនលើខេត្តរបស់អ្នកទេ។ រូបភាពដែលមានពពក ៥០% អាចស្អាតលើខេត្តរបស់អ្នក ហើយផ្ទុយមកវិញ។ មេរៀនទី៣ បង្ហាញការលុបពពកតាមក្រឡា ដែលត្រឹមត្រូវជាង។

## ១.៦. ការយល់ច្រឡំដែលត្រូវប្រុងប្រយ័ត្ន

**១. «Earth Engine ធ្វើឲ្យលទ្ធផលត្រឹមត្រូវជាងមុន»**
Earth Engine ធ្វើឲ្យការគណនាលឿន និងធំជាងមុន ប៉ុន្តែភាពត្រឹមត្រូវនៅតែអាស្រ័យលើទិន្នន័យ វិធីសាស្ត្រ និងការផ្ទៀងផ្ទាត់។

**២. «រូបភាពបង្ហាញលើផែនទី មានន័យថាទិន្នន័យត្រូវបានទាញយក»**
ផែនទីបង្ហាញតែក្រឡាផែនទី (tiles) ដែលគណនានៅកម្រិត zoom បច្ចុប្បន្ន។ ទិន្នន័យពិតនៅលើម៉ាស៊ីនមេ។ ចង់បានឯកសារ ត្រូវប្រើ Export។

**៣. «Earth Engine ជំនួស QGIS ទាំងស្រុង»**
វាល្អសម្រាប់ការគណនាធំ ប៉ុន្តែខ្សោយសម្រាប់ការកែសម្រួលវ៉ិចទ័រ និងប្លង់ផែនទីបោះពុម្ព។

**៤. «ទិន្នន័យក្នុងកាតាឡុកត្រឹមត្រូវជានិច្ច»**
ទិន្នន័យនីមួយៗមានដែនកំណត់ និងកំណែរបស់វា។ ត្រូវអានការពិពណ៌នាក្នុងកាតាឡុក (ក្រុមរលក មាត្រដ្ឋាន ការកែតម្រូវ) មុនប្រើ។

**៥. «ឥតគិតថ្លៃ មានន័យថាគ្មានលក្ខខណ្ឌ»**
ការប្រើពាណិជ្ជកម្មមានលក្ខខណ្ឌ ហើយគណនីនីមួយៗមានកំណត់ការគណនា។

## ១.៧. សេចក្ដីសង្ខេបមេរៀន

ការវិភាគលើតំបន់ធំ និងរយៈពេលវែង ត្រូវការរូបភាពរាប់ពាន់ផ្ទាំង ដែលហួសសមត្ថភាពកុំព្យូទ័រផ្ទាល់ខ្លួន ទាំងក្នុងការទាញយក ការរក្សាទុក និងការគណនា។ ការគណនាលើពពកដោះស្រាយបញ្ហានេះ ដោយនាំកូដទៅកន្លែងទិន្នន័យ ហើយបញ្ជូនមកវិញតែលទ្ធផល។

Google Earth Engine រួមបញ្ចូលកាតាឡុកទិន្នន័យដ៏ធំ ម៉ាស៊ីនគណនាស្របគ្នា និង Code Editor ក្នុងកម្មវិធីរុករក។ វាល្អសម្រាប់ការងារធំ ដែលប្រើទិន្នន័យក្នុងកាតាឡុក ហើយប្រើរួមជាមួយ QGIS សម្រាប់ការងារបញ្ចប់។

## ១.៩. សំណួររំលឹក និងវាយតម្លៃ

### ក. សំណួរយល់ដឹង

1. រាយបញ្ហាបីកម្រិត ដែលធ្វើឲ្យការវិភាគទ្រង់ទ្រាយធំពិបាកលើកុំព្យូទ័រផ្ទាល់ខ្លួន។
2. ពន្យល់គំនិត «នាំកូដទៅកន្លែងទិន្នន័យ» ដោយប្រើឧទាហរណ៍មួយ។
3. រាយផ្នែកប្រាំមួយនៃ Earth Engine និងតួនាទីរបស់នីមួយៗ។
4. ហេតុអ្វី `CLOUDY_PIXEL_PERCENTAGE` មិនប្រាប់ពពកលើតំបន់សិក្សារបស់អ្នកឲ្យបានត្រឹមត្រូវ?
5. តំបន់បួនក្នុង Code Editor មានអ្វីខ្លះ?

### ខ. សំណួរអនុវត្តគោលគំនិត

6. គណនាចំនួនរូបភាព និងទំហំទិន្នន័យ សម្រាប់ Landsat 8 លើកម្ពុជា ៥ ឆ្នាំ (ប្រហែល ១០ path/row · ២៣ រូបភាព/ឆ្នាំ · ១ GB/រូបភាព)។
7. ក្នុងស្គ្រីបដំបូង ហេតុអ្វីប្រើ `max: 3000` សម្រាប់ Sentinel-2 L2A?
8. សម្រាប់កិច្ចការនីមួយៗ ជ្រើស Earth Engine ឬ QGIS ព្រមហេតុផល៖ (ក) ផែនទីផ្លូវក្នុងឃុំមួយពីរូបភាពដ្រូន (ខ) ផ្ទៃស្រែប្រចាំឆ្នាំនៃខេត្តបាត់ដំបង ២០១៧–២០២៤ (គ) ប្លង់ផែនទីរបាយការណ៍។
9. ហេតុអ្វីការគណនាលើពពក មិនដោះស្រាយបញ្ហាពពកនៅលើរូបភាព?
10. ស្នើជំហានដំបូងបីសម្រាប់ស្ថានភាពបើកមេរៀន (ផែនទីទឹកទន្លេសាប ១០ ឆ្នាំ)។

### គ. កិច្ចការខ្លី

ស្វែងរកក្នុងកាតាឡុក Earth Engine (developers.google.com/earth-engine/datasets) នូវទិន្នន័យបីដែលអ្នកគិតថាមានប្រយោជន៍សម្រាប់កម្ពុជា។ សម្រាប់នីមួយៗ សរសេរ៖ ឈ្មោះ ID គុណភាពបង្ហាញលំហ រយៈពេល និងសំណួរមួយដែលវាអាចឆ្លើយ។
