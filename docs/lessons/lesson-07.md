# មេរៀនទី៧៖ ទឹកលើផ្ទៃដី និងទឹកជំនន់ដោយ Sentinel-1

!!! info "ព័ត៌មានមេរៀន"
    **រយៈពេលបង្រៀនដែលស្នើ៖ ៣ ម៉ោង** · មេរៀនទី ៧ ក្នុងចំណោម ១៥

[:material-presentation-play: ស្លាយបង្រៀនមេរៀននេះ](../slides/lesson-07.html){ .md-button target="_blank" }

ទឹកជំនន់ជាគ្រោះមហន្តរាយដែលកើតញឹកញាប់បំផុតនៅកម្ពុជា៖ ទឹកជំនន់ទន្លេមេគង្គ និងទន្លេសាបរៀងរាល់ឆ្នាំ និងទឹកជំនន់ភ្លាមៗពីភ្លៀងខ្លាំង ដូចព្រឹត្តិការណ៍ខែតុលា ឆ្នាំ ២០២០ នៅខេត្តបន្ទាយមានជ័យ បាត់ដំបង និងពោធិ៍សាត់។ អ្នកសម្រេចចិត្តត្រូវការដឹងថា **ទឹកលិចនៅទីណា ប៉ុន្មាន ហើយប៉ះពាល់ស្រែ និងភូមិប៉ុណ្ណា** ក្នុងរយៈពេលពីរបីថ្ងៃ។ ប៉ុន្តែក្នុងពេលនោះ មេឃពោរពេញដោយពពក ហើយ Sentinel-2 ស្ទើរតែគ្មានប្រយោជន៍។

មេរៀននេះបង្រៀនការធ្វើផែនទីទឹក និងទឹកជំនន់ដោយ **រ៉ាដា Sentinel-1** ក្នុង Earth Engine៖ ពីការត្រង collection ការកាត់បន្ថយ speckle ការជ្រើសកម្រិតដោយ Otsu ការរកការផ្លាស់ប្ដូរមុន–ក្រោយ រហូតដល់ការដកកំហុស និងការគណនាផលប៉ះពាល់។

## ៧.១. គោលបំណងសិក្សា

បន្ទាប់ពីបញ្ចប់មេរៀន និស្សិតអាច៖

1. ពន្យល់មូលហេតុដែល SAR សមសម្រាប់ទឹកជំនន់ ហើយហេតុអ្វីទឹកស្ងប់ងងឹតក្នុងរូបភាព SAR។
2. ត្រង Sentinel-1 GRD តាមរបៀប ប៉ូលការីសាស្យុង និងគន្លង ហើយកាត់បន្ថយ speckle។
3. ធ្វើផែនទីទឹកដោយកម្រិតថេរ និងដោយ Otsu ហើយប្រៀបធៀបលទ្ធផល។
4. ធ្វើផែនទីទឹកជំនន់ដោយការរកការផ្លាស់ប្ដូរ ហើយដកទឹកអចិន្ត្រៃយ៍ តំបន់ភ្នំ និង HAND ខ្ពស់ចេញ។
5. គណនាផ្ទៃទឹកជំនន់ និងផលប៉ះពាល់លើគម្របដី ហើយរាយការណ៍ដែនកំណត់។

### ចំណេះដឹងមុនត្រូវមាន

- [មេរៀនទី៤](lesson-04.md)៖ reducer histogram pixelArea និង reducer ជាក្រុម។
- សៀវភៅទី៣៖ មូលដ្ឋាន SAR (ការចាំងត្រឡប់ ប៉ូលការីសាស្យុង speckle និង dB)។

## ៧.២. ស្ថានភាពបើកមេរៀន៖ ខែតុលា ២០២០ នៅបន្ទាយមានជ័យ

ក្រោយភ្លៀងធ្លាក់ខ្លាំងជាប់ៗគ្នាក្នុងពាក់កណ្ដាលខែតុលា ២០២០ គណៈកម្មាធិការគ្រប់គ្រងគ្រោះមហន្តរាយខេត្តបន្ទាយមានជ័យ ត្រូវការផែនទីតំបន់លិចទឹក ដើម្បីបែងចែកជំនួយ និងប៉ាន់ស្មានស្រែដែលខូចខាត។ រូបភាព Sentinel-2 ក្នុងខែនោះ ស្ទើរតែទាំងអស់មានពពកលើស ៨០%។ ក្រុមរបស់អ្នកមានតែ Earth Engine និងរយៈពេលមួយថ្ងៃ។

សំណួរដែលមេរៀននេះឆ្លើយ៖

- តើរ៉ាដា «មើលឃើញ» ទឹកក្រោមពពកយ៉ាងដូចម្ដេច?
- តើកម្រិត dB ណាបំបែកទឹក និងដី ហើយត្រូវជ្រើសវាដោយស្វ័យប្រវត្តិយ៉ាងណា?
- តើត្រូវបែងចែកទឹកជំនន់ ពីទឹកទន្លេ និងបឹងធម្មតាយ៉ាងដូចម្ដេច?
- តើផលប៉ះពាល់លើស្រែ និងប្រជាជនមានប៉ុណ្ណា ហើយផែនទីនេះទុកចិត្តបានប៉ុណ្ណា?

## ៧.៣. ទ្រឹស្ដីស្នូល

### ៧.៣.១. ហេតុអ្វីប្រើ SAR

<figure markdown>

<figcaption>រូបទី៧.១៖ ទឹកជំនន់ និងពពក មកជាមួយគ្នា។</figcaption>

!!! note "អានរូបនេះ"
    - ទឹកជំនន់នៅកម្ពុជាកើតឡើងភាគច្រើនក្នុងខែកក្កដា–តុលា ពេលពពកគ្របដណ្ដប់ច្រើនបំផុត។
    - SAR បញ្ចេញរលកមីក្រូផ្ទាល់ខ្លួន ហើយរលកនេះឆ្លងកាត់ពពកបាន។
    - ភាគរយពពកក្នុងក្រាបជាតម្លៃប្រហាក់ប្រហែល សម្រាប់បង្ហាញលំនាំរដូវ។


Sentinel-1 ជាផ្កាយរណប **SAR (Synthetic Aperture Radar)** ដែលបញ្ចេញរលកមីក្រូ C-band (រលកប្រវែង ~៥,៦ សង់ទីម៉ែត្រ) ផ្ទាល់ខ្លួន ហើយវាស់ថាមពលដែលចាំងត្រឡប់មកវិញ។ រលកនេះឆ្លងកាត់ពពក និងភ្លៀងស្រាលៗ ហើយដំណើរការទាំងថ្ងៃ និងយប់។ ដូច្នេះវាជាប្រភពទិន្នន័យសំខាន់បំផុតសម្រាប់ទឹកជំនន់នៅតំបន់ត្រូពិច។

Sentinel-1A បានថតរៀងរាល់ ១២ ថ្ងៃ ក្នុងគន្លងមួយ។ Sentinel-1B បានដំណើរការរហូតដល់ខែធ្នូ ២០២១ ហើយ Sentinel-1C ចាប់ផ្ដើមផ្ដល់ទិន្នន័យចាប់ពីឆ្នាំ ២០២៥។ ដូច្នេះចំនួនរូបភាពក្នុងមួយខែ ខុសគ្នាតាមឆ្នាំ៖ ត្រូវពិនិត្យ `size()` ជានិច្ច។

### ៧.៣.២. ទឹកងងឹត ហើយហេតុអ្វី

<figure markdown>
--8<-- "assets/svg/agv/a07-mechanisms.svg"
<figcaption>រូបទី៧.២៖ ផ្ទៃរលោងចាំងចេញ ផ្ទៃរដុបចាំងត្រឡប់។</figcaption>
</figure>

!!! note "អានរូបនេះ"
    - ទឹកស្ងប់ដូចកញ្ចក់៖ រលកចាំងចេញឆ្ងាយ ហើយត្រឡប់មកផ្កាយរណបតិចណាស់ (ងងឹត)។
    - រុក្ខជាតិលិចទឹក និងទីក្រុងចាំងពីរដង៖ ភ្លឺ មិនមែនងងឹតទេ ដូច្នេះការកំណត់កម្រិតរំលងវា។
    - ខ្យល់ខ្លាំងធ្វើឲ្យផ្ទៃទឹករដុប និងភ្លឺជាងធម្មតា៖ ជាប្រភពកំហុសមួយទៀត។


ផ្ទៃទឹកស្ងប់ដូចកញ្ចក់៖ រលករ៉ាដាចាំងចេញទៅទិសផ្ទុយ (specular reflection) ហើយត្រឡប់មកផ្កាយរណបតិចណាស់។ ក្នុងរូបភាព VV ទឹកមានតម្លៃប្រហែល **−១៨ ដល់ −២៥ dB** ខណៈដីភាគច្រើនមាន **−៥ ដល់ −១៥ dB**។ ភាពខុសគ្នានេះហើយដែលធ្វើឲ្យការធ្វើផែនទីទឹកដោយ SAR ងាយ។

ប៉ុន្តែមានករណីលើកលែងសំខាន់ៗ៖

- **រុក្ខជាតិលិចទឹក** (ស្រែដែលស្រូវខ្ពស់ ព្រៃលិចទឹក) និង **ទីក្រុងលិចទឹក** ចាំងពីរដង (double bounce) ហើយភ្លឺ មិនមែនងងឹតទេ។
- **ខ្យល់** ធ្វើឲ្យផ្ទៃទឹករដុប ហើយភ្លឺជាងធម្មតា។
- **ផ្ទៃរលោងស្ងួត** (ផ្លូវកៅស៊ូ ដីខ្សាច់រាប ដីភ្ជួររាបស្មើ) និង **ស្រមោលរ៉ាដា** នៅខ្នងភ្នំ ងងឹតដូចទឹក។

VV ជាទូទៅបំបែកទឹក និងដីបានល្អជាង VH ព្រោះកម្រិតសំឡេងរំខាន (noise floor) របស់ VH ខ្ពស់ជាង។ ក្នុងមេរៀននេះ យើងប្រើ VV ជាចម្បង។

### ៧.៣.៣. Sentinel-1 ក្នុង Earth Engine

Collection `COPERNICUS/S1_GRD` រៀបចំរួចជា **dB** ហើយបានកែ terrain រួច (orthorectified)។ ត្រងតាមលក្ខណៈសំខាន់ៗ៖

```javascript
var aoi = ee.FeatureCollection('FAO/GAUL/2015/level1')
  .filter(ee.Filter.eq('ADM1_NAME', 'Banteay Meanchey'));
var s1 = ee.ImageCollection('COPERNICUS/S1_GRD')
  .filterBounds(aoi)
  .filter(ee.Filter.eq('instrumentMode', 'IW'))                         // របៀបលើដី
  .filter(ee.Filter.listContains('transmitterReceiverPolarisation', 'VV'))
  .filter(ee.Filter.eq('orbitProperties_pass', 'DESCENDING'))           // គន្លងតែមួយ
  .select('VV');
print('ចំនួនរូបភាព', s1.size());
print('គន្លង', s1.aggregate_array('relativeOrbitNumber_start').distinct());
Map.addLayer(s1.filterDate('2020-10-15', '2020-10-31').mosaic().clip(aoi), {min: -25, max: 0}, 'VV តុលា ២០២០');
```

ហេតុអ្វីត្រូវត្រងគន្លង? រូបភាពពីគន្លង ascending និង descending មើលពីទិសខុសគ្នា ហើយមុំខុសគ្នា ដូច្នេះតម្លៃ dB លើផ្ទៃដដែលខុសគ្នា។ ពេលប្រៀបធៀបមុន–ក្រោយ ត្រូវប្រើ **pass និង relative orbit ដូចគ្នា**។

    - focal_median បន្ថយ speckle ហើយអ៊ីស្តូក្រាមក្លាយជាកំពូលពីរច្បាស់៖ ទឹក និងដី។
    - តម្រងធំពេកធ្វើឲ្យប្រឡាយ និងស្រះតូចៗបាត់។ ២–៥ ក្រឡា (២០–៥០ ម) ជាទូទៅសមរម្យ។


**Speckle** ជាសំឡេងរំខានដែលកើតពីធម្មជាតិនៃ SAR៖ រលកពីវត្ថុតូចៗជាច្រើនក្នុងក្រឡាមួយ បូក ឬលុបគ្នា ធ្វើឲ្យក្រឡាជិតគ្នាលើផ្ទៃដូចគ្នា មានតម្លៃខុសគ្នាខ្លាំង។ វិធីសាមញ្ញបំផុតគឺ **តម្រង median** ក្នុងរង្វង់ ឬការ៉េតូចមួយ៖

```javascript
var vv = s1.filterDate('2020-10-15', '2020-10-31').mosaic().clip(aoi);
var vvF = vv.focalMedian(30, 'circle', 'meters');   // កាំ ៣០ ម
```

តម្រង median រក្សាគែមបានល្អជាងតម្រងមធ្យម។ អ្នកស្រាវជ្រាវក៏ប្រើតម្រងឯកទេស (Refined Lee · Gamma MAP) ឬ **composite ពេលវេលា** (median នៃរូបភាពច្រើន) ប៉ុន្តែ composite ពេលវេលាមិនសមសម្រាប់ទឹកជំនន់រហ័សទេ ព្រោះទឹកប្ដូររៀងរាល់ថ្ងៃ។

### ៧.៣.៥. ជ្រើសកម្រិត៖ ថេរ ឬ Otsu

<figure markdown>
--8<-- "assets/svg/agv/a07-otsu.svg"
<figcaption>រូបទី៧.៤៖ កម្រិតដែលសមនឹងរូបភាពនីមួយៗ។</figcaption>
</figure>

!!! note "អានរូបនេះ"
    - Otsu ជ្រើសកម្រិតដែលបំបែកកំពូលទាំងពីរល្អបំផុត៖ នៅទីនេះ -១៤,៤ dB។
    - កម្រិតថេរ (−១៥ ដល់ −១៨ dB) ងាយប្រើ ប៉ុន្តែអាចមិនសមនឹងរូបភាព មុំ ឬខ្យល់ផ្សេងៗ។
    - Otsu ដំណើរការល្អ លុះត្រាតែតំបន់មានទាំងទឹក និងដីច្រើនគួរសម (ជ្រើស AOI ជុំវិញទឹកជំនន់)។


បន្ទាប់ពីតម្រង អ៊ីស្តូក្រាមនៃតំបន់ដែលមានទាំងទឹក និងដី មានកំពូលពីរ។ ទឹក = ក្រឡាដែលទាបជាងកម្រិតមួយ៖

```javascript
var water = vvF.lt(-16);                                            // កម្រិតថេរ
Map.addLayer(water.selfMask(), {palette: ['0000ff']}, 'ទឹក (−១៦ dB)');
```

កម្រិតថេរ (−១៥ ដល់ −១៨ dB) ងាយប្រើ ប៉ុន្តែតម្លៃល្អបំផុតប្ដូរតាមរូបភាព មុំ ខ្យល់ និងប្រភេទដី។ **វិធី Otsu** ជ្រើសកម្រិតដែលបំបែកកំពូលទាំងពីរល្អបំផុត ពីអ៊ីស្តូក្រាមនៃរូបភាពខ្លួនឯង៖

```javascript
function otsu(histogram) {
  var counts = ee.Array(ee.Dictionary(histogram).get('histogram'));
  var means = ee.Array(ee.Dictionary(histogram).get('bucketMeans'));
  var size = means.length().get([0]);
  var total = counts.reduce(ee.Reducer.sum(), [0]).get([0]);
  var sum = means.multiply(counts).reduce(ee.Reducer.sum(), [0]).get([0]);
  var mean = sum.divide(total);
  var bss = ee.List.sequence(1, size).map(function(i) {
    var aCounts = counts.slice(0, 0, i);
    var aCount = aCounts.reduce(ee.Reducer.sum(), [0]).get([0]);
    var aMean = means.slice(0, 0, i).multiply(aCounts).reduce(ee.Reducer.sum(), [0]).get([0]).divide(aCount);
    var bCount = total.subtract(aCount);
    var bMean = sum.subtract(aCount.multiply(aMean)).divide(bCount);
    return aCount.multiply(aMean.subtract(mean).pow(2)).add(bCount.multiply(bMean.subtract(mean).pow(2)));
  });
  return means.sort(bss).get([-1]);   // កម្រិតដែល between-class variance ធំបំផុត
}
var hist = vvF.reduceRegion({reducer: ee.Reducer.histogram(255, 0.1), geometry: aoi.geometry(),
                             scale: 30, maxPixels: 1e10, tileScale: 4}).get('VV');
var t = otsu(hist);
print('កម្រិត Otsu (dB)', t);
var waterOtsu = vvF.lt(ee.Number(t));
```

Otsu ដំណើរការល្អ លុះត្រាតែតំបន់មាន **ទាំងទឹក និងដីច្រើនគួរសម**។ លើតំបន់ដែលទឹកតិចជាង ៥% កំពូលទឹកមើលមិនឃើញ ហើយកម្រិតក្លាយជាចៃដន្យ។ ដូច្នេះអ្នកស្រាវជ្រាវច្រើនតែគណនាអ៊ីស្តូក្រាមលើតំបន់ជុំវិញគែមទឹក (bimodal region) ប៉ុណ្ណោះ។ ពិនិត្យកម្រិតដែលបានជានិច្ច៖ ប្រសិនបើវាក្រៅចន្លោះ −២៥ ដល់ −១០ dB មានអ្វីមួយខុស។

!!! example "ពិសោធន៍៖ កម្រិតទឹកលើរូបភាព SAR"
    ប្ដូរកម្រិត dB ទំហំតម្រង និងចុច Otsu។ ពិសោធន៍នេះប្រើរូបភាព SAR ក្លែងធ្វើពីគម្របដីពិតនៃភ្នំពេញ ដូច្នេះយើងដឹងការពិត ហើយអាចវាស់ភាពត្រឹមត្រូវ។ មើលថាតម្រងធ្វើឲ្យកំពូលពីរនៃអ៊ីស្តូក្រាមច្បាស់យ៉ាងណា។

### ៧.៣.៦. ទឹកជំនន់ = ទឹកថ្មី៖ ការរកការផ្លាស់ប្ដូរ

<figure markdown>
--8<-- "assets/svg/agv/a07-change.svg"
<figcaption>រូបទី៧.៥៖ ទឹកជំនន់ = ទឹកថ្មី។</figcaption>
</figure>

!!! note "អានរូបនេះ"
    - ផ្ទៃទឹកក្រោយព្រឹត្តិការណ៍ រួមទាំងទន្លេ និងបឹងធម្មតា៖ វាមិនមែនទឹកជំនន់ទាំងអស់ទេ។
    - ភាពខុសគ្នា (ក្រោយ − មុន) ធ្លាក់ខ្លាំង (−៣ dB ឬទាបជាង) នៅកន្លែងដែលដីក្លាយជាទឹក។
    - ប្រើរូបភាពមុន និងក្រោយ ពីគន្លងដូចគ្នា (orbit + pass) ដើម្បីកុំឲ្យភាពខុសគ្នាមកពីមុំមើល។


ផែនទីទឹកក្រោយព្រឹត្តិការណ៍ រួមទាំងទន្លេ បឹង ស្រះ និងស្រែដែលមានទឹកធម្មតា។ **ទឹកជំនន់** គឺទឹកដែលមាននៅពេលនេះ តែ **មិនមាន** ក្នុងស្ថានភាពធម្មតា។ វិធីពីរ៖

1. **ផែនទីទឹកពីរ**៖ ធ្វើផែនទីទឹកមុន និងក្រោយ ហើយទឹកជំនន់ = ទឹកក្រោយ AND មិនមែនទឹកមុន។
2. **ភាពខុសគ្នា dB**៖ ក្រោយ − មុន < −៣ dB (ដីក្លាយជាទឹក) AND ក្រោយ < កម្រិតទឹក។

```javascript
var before = s1.filterDate('2019-10-15', '2019-10-31').mosaic().focalMedian(30, 'circle', 'meters').clip(aoi);
var after  = s1.filterDate('2020-10-15', '2020-10-31').mosaic().focalMedian(30, 'circle', 'meters').clip(aoi);
var diff = after.subtract(before);                     // dB៖ ការដកស្មើនឹងផលធៀបក្នុងឯកតាលីនេអ៊ែរ
var flood = diff.lt(-3).and(after.lt(-16));
Map.addLayer(diff, {min: -10, max: 10, palette: ['blue', 'white', 'red']}, 'ក្រោយ − មុន');
Map.addLayer(flood.selfMask(), {palette: ['red']}, 'ទឹកជំនន់');
```

**រូបភាពមុន** ត្រូវតំណាង «ធម្មតា» សម្រាប់រដូវនោះ៖ ខែដូចគ្នានៃឆ្នាំមុនដែលគ្មានទឹកជំនន់ធំ ឬ median នៃខែដូចគ្នាច្រើនឆ្នាំ។ ប្រសិនបើប្រើរូបភាពរដូវប្រាំងជា «មុន» ទឹកតាមរដូវធម្មតា (ទន្លេសាបពង្រីក) នឹងរាប់ជាទឹកជំនន់ទាំងអស់។

### ៧.៣.៧. ដកកំហុសវិជ្ជមានក្លែងក្លាយ

<figure markdown>
--8<-- "assets/svg/agv/a07-masks.svg"
<figcaption>រូបទី៧.៦៖ រកទឹកបានហើយ ត្រូវសួរថា «ពិតជាទឹកជំនន់ទេ?»។</figcaption>
</figure>

!!! note "អានរូបនេះ"
    - ទឹកអចិន្ត្រៃយ៍ត្រូវដកចេញ ដើម្បីកុំឲ្យទន្លេ និងទន្លេសាបរាប់ជាទឹកជំនន់។
    - ស្រមោលរ៉ាដានៅជម្រាលភ្នំ ងងឹតដូចទឹក៖ mask តាម slope ឬ HAND។
    - ផ្ទៃរលោងស្ងួត (ផ្លូវ ដីភ្ជួររាប) ក៏ងងឹតដែរ៖ ការប្រៀបធៀបមុន–ក្រោយជួយដោះស្រាយ។


```javascript
var gsw = ee.Image('JRC/GSW1_4/GlobalSurfaceWater');
var permanent = gsw.select('seasonality').gte(10);                        // ទឹក ≥ ១០ ខែ/ឆ្នាំ
var slope = ee.Terrain.slope(ee.Image('USGS/SRTMGL1_003'));
var hand = ee.Image('MERIT/Hydro/v1_0_1').select('hnd');
var floodClean = flood
  .where(permanent.unmask(0), 0)           // ដកទឹកអចិន្ត្រៃយ៍
  .updateMask(slope.lt(5))                  // ដកតំបន់ភ្នំ និងស្រមោលរ៉ាដា
  .updateMask(hand.lt(15))                  // ដកទីខ្ពស់ពីប្រឡាយ
  .selfMask();
// ដកក្រុមក្រឡាតូចៗ (< ៨ ក្រឡាជាប់គ្នា) ដែលភាគច្រើនជាសំឡេងរំខាន
var connected = floodClean.connectedPixelCount(8, true);
floodClean = floodClean.updateMask(connected.gte(8));
Map.addLayer(floodClean, {palette: ['red']}, 'ទឹកជំនន់ (បានសម្អាត)');
```

`unmask(0)` ចាំបាច់ព្រោះ JRC គ្មានតម្លៃ (masked) នៅកន្លែងដែលមិនដែលមានទឹក៖ បើគ្មាន unmask ការ where នឹងបាត់ក្រឡាទាំងនោះ។

### ៧.៣.៨. ពីផែនទីទឹកជំនន់ ទៅជាផលប៉ះពាល់

<figure markdown>
--8<-- "assets/svg/agv/a07-exposure.svg"
<figcaption>រូបទី៧.៧៖ ស្រែប៉ុន្មានហិកតាលិចទឹក?។</figcaption>
</figure>

!!! note "អានរូបនេះ"
    - ឆ្លងផែនទីទឹកជំនន់ ជាមួយគម្របដី (ESA WorldCover ឬផែនទីមេរៀនទី៦) ដោយ reducer ជាក្រុម (មេរៀនទី៤)។
    - ដំណាំ/ស្មៅ និងដីទទេជិតទន្លេ រងផលប៉ះពាល់ច្រើនជាងគេ។
    - ឆ្លងជាមួយប្រជាជន (WorldPop) ដើម្បីប៉ាន់ស្មានចំនួនមនុស្សដែលរងផលប៉ះពាល់។


ផែនទីទឹកជំនន់មានតម្លៃពេញលេញ នៅពេលឆ្លងជាមួយស្រទាប់ផ្សេង ដោយប្រើ reducer ពីមេរៀនទី៤៖

```javascript
var km2 = ee.Image.pixelArea().divide(1e6).updateMask(floodClean)
  .reduceRegion({reducer: ee.Reducer.sum(), geometry: aoi.geometry(), scale: 10, maxPixels: 1e10, tileScale: 4});
print('ផ្ទៃទឹកជំនន់ (គម²)', km2);

var wc = ee.ImageCollection('ESA/WorldCover/v200').first();      // ៤០ = ដំណាំ
var cropKm2 = ee.Image.pixelArea().divide(1e6).updateMask(floodClean).updateMask(wc.eq(40))
  .reduceRegion({reducer: ee.Reducer.sum(), geometry: aoi.geometry(), scale: 10, maxPixels: 1e10, tileScale: 4});
var pop = ee.ImageCollection('WorldPop/GP/100m/pop').filter(ee.Filter.eq('country', 'KHM'))
  .filter(ee.Filter.eq('year', 2020)).first();
var people = pop.updateMask(floodClean.reproject(pop.projection()).unmask(0).gt(0))
  .reduceRegion({reducer: ee.Reducer.sum(), geometry: aoi.geometry(), scale: 100, maxPixels: 1e10});
print('ដីដំណាំលិច (គម²)', cropKm2, 'ប្រជាជនក្នុងតំបន់លិច', people);
```

ចំណាំថា WorldPop មានក្រឡា ១០០ ម៉ែត្រ។ ការគណនាប្រជាជនត្រូវធ្វើនៅ scale ១០០ ម ហើយក្រឡាដែលលិចមួយផ្នែកត្រូវបានរាប់ទាំងមូល ដូច្នេះលទ្ធផលជាការប៉ាន់ស្មានខ្ពស់ (upper estimate)។

## ៧.៤. ឧទាហរណ៍ដែលបានដោះស្រាយ៖ ទឹកជំនន់ខែតុលា ២០២០ ខេត្តបន្ទាយមានជ័យ

ឧទាហរណ៍នេះផ្អែកលើលំហាត់ក្នុងសៀវភៅចាស់របស់វគ្គនេះ ដោយបន្ថែមតម្រង Otsu និងការសម្អាត។

### ជំហានទី១៖ Collection និងរូបភាពពីរ

ប្រើកូដក្នុងផ្នែក ៧.៣.៣ ដើម្បីបាន `s1` (VV · descending)។ បង្កើត `before` (១៥–៣១ តុលា ២០១៩) និង `after` (១៥–៣១ តុលា ២០២០)។ ពិនិត្យ `size()` នៃរយៈពេលនីមួយៗ៖ ប្រសិនបើ ០ ពង្រីករយៈពេល។

### ជំហានទី២៖ មើលដោយភ្នែកមុន

```javascript
Map.centerObject(aoi, 9);
Map.addLayer(before.addBands(after).addBands(after), {min: -25, max: -5}, 'RGB៖ មុន ក្រោយ ក្រោយ');
```

ក្នុងរូបភាពបីក្រុមរលកនេះ តំបន់ដែលក្លាយជាទឹក បង្ហាញជា **ពណ៌ក្រហម** (ភ្លឺក្នុងរូបភាពមុន ងងឹតក្នុងរូបភាពក្រោយ)។ វាជាការពិនិត្យរហ័ស មុនពេលគណនាអ្វីទាំងអស់។

### ជំហានទី៣៖ កម្រិត Otsu និងការផ្លាស់ប្ដូរ

គណនា Otsu លើ `after` (ផ្នែក ៧.៣.៥) ហើយប្រើកម្រិតនោះជំនួស −១៦ ក្នុងកូដផ្នែក ៧.៣.៦។ ប្រៀបធៀបផ្ទៃទឹកជំនន់ពីកម្រិតទាំងពីរ។

### ជំហានទី៤៖ សម្អាត និងគណនាផ្ទៃ

អនុវត្ត mask ក្នុងផ្នែក ៧.៣.៧ ហើយគណនាផ្ទៃសរុប និងផ្ទៃដីដំណាំលិច (ផ្នែក ៧.៣.៨)។ គណនាតាមស្រុកដោយ reduceRegions (GAUL level 2) ដើម្បីកំណត់ស្រុកដែលរងផលប៉ះពាល់ខ្លាំងជាងគេ។

### ជំហានទី៥៖ ផ្ទៀងផ្ទាត់ និងនាំចេញ

ពិនិត្យលទ្ធផលជាមួយរបាយការណ៍ព័ត៌មាន ឬរបាយការណ៍របស់ NCDM អំពីស្រុកដែលរងទឹកជំនន់ ហើយមើលរូបភាព Sentinel-2 ដែលមានចន្លោះពពកណាមួយ។ នាំចេញជា GeoTIFF (`toByte()`) និងតារាងស្រុកជា CSV។

> «ទឹកជំនន់ខែតុលា ២០២០ ត្រូវបានធ្វើផែនទីពី Sentinel-1 VV (descending) ដោយប្រៀបធៀបជាមួយខែតុលា ២០១៩ កម្រិត Otsu និងការដកទឹកអចិន្ត្រៃយ៍ (JRC) ជម្រាល > ៥° និង HAND > ១៥ ម។ ផ្ទៃទឹកជំនន់តាមស្រុក និងដីដំណាំលិច ត្រូវបានគណនាដោយ pixelArea។»

!!! warning "អ្វីដែលយើងមិនអាចសន្និដ្ឋាន"
    ផែនទីនេះបង្ហាញទឹកនៅម៉ោងដែលផ្កាយរណបឆ្លងកាត់ (ប្រហែលម៉ោង ៦ ព្រឹក សម្រាប់ descending) មិនមែនទឹកអតិបរមាទេ។ វារំលងទឹកក្រោមរុក្ខជាតិក្រាស់ និងក្នុងទីក្រុង ហើយមិនប្រាប់ពីជម្រៅទឹកទេ។ ស្រែដែលមានទឹកធម្មតាក្នុងខែតុលា ប៉ុន្តែមិនមានក្នុងឆ្នាំ ២០១៩ ក៏អាចត្រូវរាប់ជាទឹកជំនន់ដែរ។

## ៧.៥. សកម្មភាពអនុវត្ត

- **លំហាត់ទី៧**៖ ធ្វើផែនទីផ្ទៃទឹកទន្លេសាប រដូវប្រាំង និងរដូវទឹកឡើង ពី Sentinel-1 ជាមួយ Otsu គណនាផ្ទៃលិចតាមខេត្តជុំវិញបឹង ហើយប្រៀបធៀបជាមួយ JRC។ មើល [លំហាត់ទី៧](../workbook/lab-07.md)។
- **ក្នុងថ្នាក់**៖ ក្រុមនីមួយៗរត់ឧទាហរណ៍បន្ទាយមានជ័យ ជាមួយកម្រិតខុសគ្នា (−១៤ −១៦ −១៨ dB · Otsu) ហើយប្រៀបធៀបផ្ទៃទឹកជំនន់។

## ៧.៦. ការយល់ច្រឡំដែលត្រូវប្រុងប្រយ័ត្ន

**១. «ក្រឡាងងឹតក្នុង SAR តែងតែជាទឹក»**
ផ្លូវកៅស៊ូ ដីខ្សាច់រាប និងស្រមោលរ៉ាដានៅភ្នំ ក៏ងងឹតដែរ។ ត្រូវប្រើការប្រៀបធៀបមុន–ក្រោយ និង mask ជម្រាល។

**២. «រ៉ាដាមើលឃើញទឹកជំនន់គ្រប់ទីកន្លែង»**
ទឹកក្រោមព្រៃ ឬរវាងអគារ ចាំងពីរដង ហើយភ្លឺ។ ផែនទី SAR ធម្មតាប៉ាន់ស្មានទឹកជំនន់ក្នុងទីក្រុង និងព្រៃលិចទឹកទាបជាងការពិត។

**៣. «−១៦ dB ជាកម្រិតទឹកសកល»**
កម្រិតប្ដូរតាមរូបភាព មុំ ខ្យល់ និងប៉ូលការីសាស្យុង។ ប្រើ Otsu ឬពិនិត្យអ៊ីស្តូក្រាមរាល់ពេល។

**៤. «រូបភាពរដូវប្រាំង ជារូបភាព "មុន" ល្អបំផុត»**
វាធ្វើឲ្យទឹកតាមរដូវធម្មតារាប់ជាទឹកជំនន់។ ប្រើខែដូចគ្នានៃឆ្នាំធម្មតា។

**៥. «ផែនទីទឹកជំនន់បង្ហាញទឹកអតិបរមា»**
វាបង្ហាញតែពេលដែលផ្កាយរណបឆ្លងកាត់។ ទឹកអាចឡើងខ្ពស់ជាងនេះ ៣–៥ ថ្ងៃមុន ឬក្រោយ។

## ៧.៧. សេចក្ដីសង្ខេបមេរៀន

Sentinel-1 ឆ្លងកាត់ពពក ហើយទឹកស្ងប់ងងឹតក្នុងរូបភាព VV (−១៨ ដល់ −២៥ dB) ព្រោះរលកចាំងចេញឆ្ងាយ។ ក្នុង Earth Engine យើងត្រង S1_GRD តាម IW VV និងគន្លងតែមួយ កាត់បន្ថយ speckle ដោយ focalMedian ហើយបំបែកទឹកដោយកម្រិតថេរ ឬ Otsu ដែលគណនាពីអ៊ីស្តូក្រាមនៃរូបភាពនីមួយៗ។

ទឹកជំនន់គឺជាទឹកថ្មី៖ ប្រៀបធៀបជាមួយរូបភាពនៃខែដូចគ្នាក្នុងឆ្នាំធម្មតា ដកទឹកអចិន្ត្រៃយ៍ (JRC) តំបន់ជម្រាល និង HAND ខ្ពស់ ហើយបន្ទាប់មកគណនាផ្ទៃ និងផលប៉ះពាល់ដោយ pixelArea WorldCover និង WorldPop។

!!! abstract "គំនិតស្នូលនៃមេរៀន"
    SAR ប្រាប់ថា «ផ្ទៃនេះរលោងដូចទឹក» មិនមែន «នេះជាទឹកជំនន់» ទេ។ ផែនទីទឹកជំនន់ដែលទុកចិត្តបាន ត្រូវការការប្រៀបធៀបជាមួយស្ថានភាពធម្មតា និងការដកចេញនូវអ្វីៗដែលងងឹតដូចទឹក។

8. ហេតុអ្វី `after.subtract(before)` ក្នុង dB ស្មើនឹងផលធៀបក្នុងឯកតាលីនេអ៊ែរ?
9. ផែនទីទឹកជំនន់បង្ហាញក្រឡាតូចៗរាយប៉ាយច្រើនលើភ្នំ។ ស្នើដំណោះស្រាយពីរ។
10. ហេតុអ្វីចំនួនប្រជាជនរងផលប៉ះពាល់ពី WorldPop ជាការប៉ាន់ស្មានខ្ពស់?

### គ. កិច្ចការខ្លី

ធ្វើផែនទីទឹកជំនន់នៃព្រឹត្តិការណ៍មួយផ្សេងទៀតនៅកម្ពុជា ដែលកើតក្រោយឆ្នាំ ២០១៥ (Sentinel-1 មានទិន្នន័យលើកម្ពុជាជាប្រចាំចាប់ពីប្រហែលឆ្នាំនោះ)។ សរសេររបាយការណ៍មួយទំព័រ៖ វិធីសាស្ត្រ កម្រិត ផ្ទៃ និងដែនកំណត់។

## កំណត់សម្គាល់សម្រាប់គ្រូបង្រៀន

### ក. ការបែងចែកពេលវេលា ១៨០ នាទី

| សកម្មភាព | ពេលវេលា |
|---|---:|
| ស្ថានភាពបើកមេរៀន៖ តុលា ២០២០ | ១០ នាទី |
| ហេតុអ្វី SAR · យន្តការចាំង | ២០ នាទី |
| Sentinel-1 ក្នុង Earth Engine · speckle | ២៥ នាទី |
| កម្រិតថេរ និង Otsu · ពិសោធន៍ | ៣៥ នាទី |
| ការរកការផ្លាស់ប្ដូរ | ២០ នាទី |

### ខ. ចំណាំអំពីទិន្នន័យ

- ពិសោធន៍ក្នុងមេរៀននេះ ប្រើរូបភាព SAR ក្លែងធ្វើ ដែលបង្កើតពីគម្របដីពិតនៃរូបភាព Landsat 8 ភ្នំពេញ (តម្លៃ dB ធម្មតាតាមប្រភេទគម្របដី + speckle)។ ប្រាប់និស្សិតថាវាមិនមែនរូបភាព Sentinel-1 ពិតទេ។
- សម្រាប់ការឆ្លើយតបពេលមានគ្រោះពិត UN-SPIDER មានកម្មវិធី Earth Engine គំរូសម្រាប់ទឹកជំនន់ ដែលគួរណែនាំនិស្សិតឲ្យស្គាល់។

### គ. ការភ្ជាប់ទៅមេរៀនបន្ទាប់

ទឹកជំនន់ និងគ្រោះរាំងស្ងួត ជាមុខពីរនៃកាក់តែមួយ៖ ឆ្នាំខ្លះភ្លៀងច្រើនពេក ឆ្នាំខ្លះភ្លៀងតិចពេក ជួនកាលក្នុងខេត្តតែមួយ។ ប៉ុន្តែគ្រោះរាំងស្ងួតមិនបង្ហាញខ្លួនជាផ្ទៃទឹកដែលយើងអាចកំណត់កម្រិតបានទេ។

> តើត្រូវវាស់ «ភ្លៀងតិចជាងធម្មតា» និង «រុក្ខជាតិខ្វះទឹក» យ៉ាងដូចម្ដេច នៅពេលដែល «ធម្មតា» ខុសគ្នាតាមទីកន្លែង និងខែ?

សំណួរនេះនាំទៅ **មេរៀនទី៨៖ គ្រោះរាំងស្ងួត ទឹកភ្លៀង និងសុខភាពរុក្ខជាតិ**។
