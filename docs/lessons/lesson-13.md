# មេរៀនទី១៣៖ ការវិភាគពហុលក្ខខណ្ឌជាមួយទិន្នន័យ RS

    **រយៈពេលបង្រៀនដែលស្នើ៖ ៣ ម៉ោង** · មេរៀនទី ១៣ ក្នុងចំណោម ១៥

មេរៀនមុនៗបានផ្ដល់ស្រទាប់ជាច្រើន៖ ជម្រាល HAND ទឹកភ្លៀង VHI ផែនទីស្រែ ព្រៃ ទីក្រុង និង LST។ ប៉ុន្តែសំណួរជាក់ស្ដែងកម្រត្រូវការស្រទាប់តែមួយណាស់។ «តើគួរជីកស្រះសហគមន៍នៅទីណា ដើម្បីជួយស្រែនៅរដូវរាំងស្ងួត?» «តើកន្លែងណាសមសម្រាប់ជម្រកសង្គ្រោះពេលទឹកជំនន់?» សំណួរទាំងនេះត្រូវការ **រួមបញ្ចូលលក្ខខណ្ឌច្រើន** ដែលមានឯកតាខុសគ្នា និងសារៈសំខាន់ខុសគ្នា។

មេរៀននេះបង្រៀន **ការវិភាគពហុលក្ខខណ្ឌ (Multi-Criteria Decision Analysis · MCDA)** ក្នុង Earth Engine៖ ការបែងចែកកត្តា និងឧបសគ្គ ការធ្វើស្តង់ដារ ការកំណត់ទម្ងន់ដោយ AHP ការបូកបញ្ចូលដោយ Weighted Linear Combination ការវិភាគភាពរសើប និងការបម្លែងផែនទីទៅជាទីតាំងបេក្ខភាព។

## ១៣.១. គោលបំណងសិក្សា

បន្ទាប់ពីបញ្ចប់មេរៀន និស្សិតអាច៖

1. បម្លែងសំណួរទីតាំង ទៅជាកត្តា និងឧបសគ្គ ដែលអាចវាស់បានពីទិន្នន័យ Earth Engine។
2. ធ្វើស្តង់ដារកត្តាទៅជាមាត្រដ្ឋាន ០–១ ដោយមុខងារលីនេអ៊ែរ និង fuzzy។
3. គណនាទម្ងន់ដោយ AHP ហើយពិនិត្យ consistency ratio។
4. គណនាផែនទីភាពសមស្រប (WLC) ដាក់ឧបសគ្គ ហើយកំណត់ទីតាំងបេក្ខភាព។
5. ធ្វើការវិភាគភាពរសើប ហើយពន្យល់ថាលទ្ធផលរឹងមាំប៉ុណ្ណា។

## ១៣.២. ស្ថានភាពបើកមេរៀន៖ ស្រះសហគមន៍នៅខេត្តកំពង់ស្ពឺ

គម្រោងមួយមានថវិកាសម្រាប់ជីក **ស្រះសហគមន៍ ២០** នៅខេត្តកំពង់ស្ពឺ ដើម្បីស្តុកទឹកភ្លៀងសម្រាប់ស្រែក្នុងរយៈពេលស្ងួត (មេរៀនទី៨)។ ក្រុមបច្ចេកទេសកំណត់លក្ខខណ្ឌ៖ ដីរាបស្មើ ដីឥដ្ឋច្រើន (ទប់ទឹកបាន) ជិតស្រែ ទឹកភ្លៀងគ្រប់គ្រាន់ មិននៅក្នុងព្រៃ តំបន់ការពារ ទឹកអចិន្ត្រៃយ៍ ឬភូមិ។ ពួកគេចង់បានបញ្ជីទីតាំងបេក្ខភាព ដើម្បីចុះពិនិត្យវាល។

សំណួរដែលមេរៀននេះឆ្លើយ៖

- តើលក្ខខណ្ឌនីមួយៗក្លាយជាស្រទាប់រ៉ាស្ទ័រយ៉ាងដូចម្ដេច?
- តើត្រូវបូក ដឺក្រេ ម៉ែត្រ មីលីម៉ែត្រ និង % ចូលគ្នាដោយរបៀបណា?
- តើលក្ខខណ្ឌណាសំខាន់ជាង ហើយនរណាសម្រេច?
- តើលទ្ធផលប្ដូរប៉ុណ្ណា ប្រសិនបើយើងប្ដូរទម្ងន់?

### ១៣.៣.១. លំហូរការងារ MCDA

<figure markdown>
--8<-- "assets/svg/agv/a13-workflow.svg"
<figcaption>រូបទី១៣.១៖ ប្រាំមួយជំហាន ពីសំណួរទៅទីតាំង។</figcaption>
</figure>

!!! note "អានរូបនេះ"
    - កត្តា (factor) មានកម្រិតល្អ–អាក្រក់ជាបន្ត៖ ជម្រាល ចម្ងាយ ទឹកភ្លៀង។ ឧបសគ្គ (constraint) ជា បាទ/ទេ៖ ព្រៃការពារ ទឹក ភូមិ។
    - កត្តាត្រូវបម្លែងទៅជាមាត្រដ្ឋានដូចគ្នា (០–១) មុនបូកបញ្ចូល។
    - Weighted Linear Combination (WLC) = ផលបូកមានទម្ងន់ ហើយឧបសគ្គគុណដើម្បីដកចេញ។


MCDA មានប្រាំមួយជំហាន៖ (១) សំណួរ និងអ្នកសម្រេចចិត្ត (២) លក្ខខណ្ឌ (៣) ស្តង់ដារ (៤) ទម្ងន់ (៥) បូកបញ្ចូល និងដាក់ឧបសគ្គ (៦) ពិនិត្យភាពរសើប និងផ្ទៀងផ្ទាត់នៅវាល។ ចំណុចសំខាន់គឺបែងចែក៖

- **កត្តា (factor)**៖ លក្ខខណ្ឌដែលមានកម្រិតល្អ–អាក្រក់ជាបន្ត ហើយអាចទូទាត់គ្នាបាន (ជម្រាលតិចជាងបន្តិច អាចទូទាត់ដោយដីឥដ្ឋច្រើន)។
- **ឧបសគ្គ (constraint)**៖ លក្ខខណ្ឌ បាទ/ទេ ដែលមិនអាចទូទាត់ (តំបន់ការពារ ទឹកអចិន្ត្រៃយ៍)។

### ១៣.៣.២. ពីលក្ខខណ្ឌ ទៅស្រទាប់

| លក្ខខណ្ឌ | ប្រភេទ | ទិន្នន័យ Earth Engine |
|---|---|---|
| ជម្រាលតិច | កត្តា | `USGS/SRTMGL1_003` → ee.Terrain.slope |
| ជិតស្រែ | កត្តា | `ESA/WorldCover/v200` (៤០) → fastDistanceTransform |
| ដីឥដ្ឋច្រើន | កត្តា | `OpenLandMap/SOL/SOL_CLAY-WFRACTION_USDA-3A1A1A_M/v02` |
| ទឹកភ្លៀងគ្រប់គ្រាន់ | កត្តា | `UCSB-CHG/CHIRPS/DAILY` (សរុបប្រចាំឆ្នាំ) |
| មិនមែនព្រៃ ទឹក ទីក្រុង | ឧបសគ្គ | WorldCover ១០ · ៥០ · ៨០ · JRC |
| មិននៅតំបន់ការពារ | ឧបសគ្គ | `WCMC/WDPA/current/polygons` |

```javascript
var aoi = ee.FeatureCollection('FAO/GAUL/2015/level1').filter(ee.Filter.eq('ADM1_NAME', 'Kampong Speu'));
var slope = ee.Terrain.slope(ee.Image('USGS/SRTMGL1_003'));
var wc = ee.ImageCollection('ESA/WorldCover/v200').first();
var distCrop = wc.eq(40).selfMask().unmask(0).fastDistanceTransform(256).sqrt()
  .multiply(ee.Image.pixelArea().sqrt()).reproject({crs: 'EPSG:32648', scale: 30}).rename('distCrop');   // ម៉ែត្រ
var clay = ee.Image('OpenLandMap/SOL/SOL_CLAY-WFRACTION_USDA-3A1A1A_M/v02').select('b30').rename('clay');   // % នៅ ៣០ សម
var rain = ee.ImageCollection('UCSB-CHG/CHIRPS/DAILY').filterDate('2004-01-01', '2024-01-01').sum().divide(20).rename('rain');
```

`fastDistanceTransform` ផ្ដល់ចម្ងាយការ៉េជាក្រឡា ដូច្នេះយើងយកឫសការ៉េ ហើយគុណនឹងទំហំក្រឡា។ `reproject` ធានាថាការគណនាធ្វើនៅក្រឡា ៣០ ម មិនមែននៅកម្រិតពីរ៉ាមីតដែលប្ដូរតាម zoom ទេ។ ចំណាំថា OpenLandMap មានក្រឡា ២៥០ ម និងជាការព្យាករពីម៉ូដែល៖ វាប្រាប់លំនាំទូទៅ មិនមែនដីនៃស្រែមួយៗទេ។

### ១៣.៣.៣. ស្តង់ដារ

<figure markdown>
--8<-- "assets/svg/agv/a13-standardize.svg"
<figcaption>រូបទី១៣.២៖ ឯកតាខុសគ្នា ត្រូវបម្លែងមុន។</figcaption>

!!! note "អានរូបនេះ"
    - ដឺក្រេ ម៉ែត្រ mm និង % មិនអាចបូកគ្នាបានទេ៖ បម្លែងទាំងអស់ទៅ ០ (អាក្រក់) ដល់ ១ (ល្អ)។
    - កត្តាខ្លះ «កាន់តែតិចកាន់តែល្អ» (ជម្រាល ចម្ងាយ)៖ ត្រូវបញ្ច្រាសទិស។
    - ចំណុចបត់ (ឧ. ១° និង ៦°) មកពីអក្សរសិល្ប៍ ឬអ្នកជំនាញ៖ ត្រូវរាយការណ៍វា។ ក្នុង Earth Engine៖ unitScale() និង clamp()។


កត្តានីមួយៗត្រូវបម្លែងទៅជា **០ (អាក្រក់បំផុត) ដល់ ១ (ល្អបំផុត)**។ មុខងារដែលប្រើញឹកញាប់៖

- **លីនេអ៊ែរ**៖ `img.unitScale(a, b).clamp(0, 1)` សម្រាប់កត្តា «កាន់តែច្រើន កាន់តែល្អ»។
- **លីនេអ៊ែរបញ្ច្រាស**៖ `ee.Image(1).subtract(img.unitScale(a, b).clamp(0, 1))` សម្រាប់ «កាន់តែតិច កាន់តែល្អ»។
- **Fuzzy (sigmoid)**៖ ការប្ដូររលោងជុំវិញចំណុចកណ្ដាល ដែលល្អសម្រាប់លក្ខខណ្ឌដែលមានកម្រិតសំខាន់មួយ។

```javascript
function up(img, a, b) { return img.unitScale(a, b).clamp(0, 1); }
function down(img, a, b) { return ee.Image(1).subtract(up(img, a, b)); }
var fSlope = down(slope, 1, 6).rename('fSlope');         // ≤ ១° ល្អ · ≥ ៦° អាក្រក់
var fCrop = down(distCrop, 0, 1500).rename('fCrop');     // ជិតស្រែល្អ
var fClay = up(clay, 15, 45).rename('fClay');            // ដីឥដ្ឋ ≥ ៤៥% ល្អ
var fRain = up(rain, 1100, 1800).rename('fRain');
```

ចំណុចបត់ (១° ៦° ១៥០០ ម …) ជាការសម្រេចចិត្តបច្ចេកទេស ដែលគួរមកពីអក្សរសិល្ប៍ គោលការណ៍ណែនាំ ឬអ្នកជំនាញក្នុងស្រុក ហើយត្រូវរាយការណ៍ក្នុងវិធីសាស្ត្រ។

!!! note "អានរូបនេះ"
    - «ជម្រាលសំខាន់ជាងទឹកភ្លៀង ៤ ដង»៖ ការសម្រេចពីរៗ ងាយជាងការដាក់ទម្ងន់ ៤ ក្នុងពេលតែមួយ។
    - ទម្ងន់ពី AHP៖ ជម្រាល ៤៧%, ចម្ងាយពីដំណាំ ១៦%, ដីឥដ្ឋ ២៨%, ទឹកភ្លៀង ១០%។
    - CR (consistency ratio) < ០,១៖ ការសម្រេចមិនផ្ទុយគ្នាខ្លាំង។ តួលេខគណនាពិតពីម៉ាទ្រីសនេះ។


**AHP (Analytic Hierarchy Process · Saaty)** ស្នើឲ្យអ្នកជំនាញប្រៀបធៀបលក្ខខណ្ឌម្ដងពីរ៖ «ជម្រាលសំខាន់ជាងទឹកភ្លៀងប៉ុន្មានដង?» នៅលើមាត្រដ្ឋាន ១ (ស្មើ) ដល់ ៩ (សំខាន់ជាងខ្លាំងបំផុត)។ ម៉ាទ្រីសដែលបាន មានលក្ខណៈច្រាស (a_ji = ១ / a_ij)។ ទម្ងន់គឺជា eigenvector អតិបរមា ដែលធ្វើឲ្យផលបូកស្មើ ១។

**Consistency ratio (CR)** វាស់ថាការសម្រេចផ្ទុយគ្នាប៉ុណ្ណា (ឧ. ក > ខ ខ > គ ប៉ុន្តែ គ > ក)។ **CR < ០,១** ជាទូទៅទទួលយកបាន។ ក្នុងឧទាហរណ៍នេះ ម៉ាទ្រីសផ្ដល់ទម្ងន់ ជម្រាល ៤៧% ដីឥដ្ឋ ២៨% ចម្ងាយពីស្រែ ១៦% និងទឹកភ្លៀង ១០% ជាមួយ CR ប្រហែល ០,០១។ ការគណនា AHP ធ្វើក្នុង Excel QGIS ឬ Python ហើយយកតែទម្ងន់មកប្រើក្នុង Earth Engine។

វិធីសាមញ្ញជាងនេះ៖ **ចំណាត់ថ្នាក់** (rank sum)៖ ដាក់លក្ខខណ្ឌតាមលំដាប់ ហើយទម្ងន់ = (n − r + ១) / Σ។ សម្រាប់ ៤ លក្ខខណ្ឌ៖ ៤០% ៣០% ២០% ១០%។

### ១៣.៣.៥. Weighted Linear Combination និងឧបសគ្គ

<figure markdown>
--8<-- "assets/svg/agv/a13-wlc.svg"
<figcaption>រូបទី១៣.៤៖ ផែនទីភាពសមស្រប។</figcaption>
</figure>

!!! note "អានរូបនេះ"
    - ក្រឡានីមួយៗទទួលពិន្ទុ ០–១៖ ផលបូកមានទម្ងន់នៃកត្តាស្តង់ដារ។
    - ពិន្ទុខ្ពស់នៅកន្លែងដែលរាបស្មើ ជិតដំណាំ និងដីឥដ្ឋច្រើន៖ ប៉ុន្តែកត្តាខ្សោយមួយអាចត្រូវបានទូទាត់ដោយកត្តាល្អ (compensation)។
    - ប្រសិនបើកត្តាណាមួយមិនអាចទូទាត់បាន (ឧ. ជម្រាល > ១០°) វាត្រូវតែជាឧបសគ្គ មិនមែនកត្តាទេ។


```javascript
var W = {slope: 0.47, crop: 0.16, clay: 0.28, rain: 0.09};      // ពី AHP
var S = fSlope.multiply(W.slope).add(fCrop.multiply(W.crop))
  .add(fClay.multiply(W.clay)).add(fRain.multiply(W.rain)).rename('S');
```

<figcaption>រូបទី១៣.៥៖ ឧបសគ្គជា ០ ឬ ១។</figcaption>
</figure>

!!! note "អានរូបនេះ"
    - ឧបសគ្គមកពីច្បាប់ (តំបន់ការពារ) រូបវិទ្យា (ទឹក ជម្រាល) ឬសង្គម (ចម្ងាយពីភូមិ ផ្លូវ)។
    - ក្នុង Earth Engine៖ updateMask() ជាមួយរូបភាព ០/១ ឬ where() ដើម្បីដាក់ពិន្ទុ ០។
    - ឧបសគ្គច្រើនពេក អាចមិនសល់ទីតាំងណាទេ៖ ពិនិត្យផ្ទៃដែលនៅសល់ជានិច្ច។


```javascript
var pa = ee.FeatureCollection('WCMC/WDPA/current/polygons').filter(ee.Filter.eq('ISO3', 'KHM'));
var notPA = ee.Image(1).paint(pa, 0);                             // ០ ក្នុងតំបន់ការពារ
var jrc = ee.Image('JRC/GSW1_4/GlobalSurfaceWater').select('occurrence').unmask(0);
var ok = notPA.and(wc.neq(10)).and(wc.neq(50)).and(wc.neq(80)).and(jrc.lt(20)).and(slope.lt(8));
var suit = S.updateMask(ok).clip(aoi);
Map.addLayer(suit, {min: 0.2, max: 0.9, palette: ['#d7191c', '#fdae61', '#ffffbf', '#a6d96a', '#1a9641']}, 'ភាពសមស្រប');
```

WLC អនុញ្ញាតឲ្យ **ទូទាត់** (compensation)៖ ដីឥដ្ឋល្អខ្លាំង អាចទូទាត់ចម្ងាយពីស្រែឆ្ងាយបន្តិច។ ប្រសិនបើលក្ខខណ្ឌណាមួយមិនអាចទូទាត់បាន ត្រូវប្ដូរវាទៅជាឧបសគ្គ។ `paint(pa, 0)` បង្កើតរូបភាពដែលមានតម្លៃ ០ ក្នុងពហុកោណ ហើយ ១ នៅកន្លែងផ្សេង។

!!! note "អានរូបនេះ"

    - រាយការណ៍ទីតាំងដែលល្អក្នុងគ្រប់សេណារីយ៉ូ ជាការណែនាំដែលរឹងមាំជាងគេ។


ទម្ងន់មកពីការវិនិច្ឆ័យរបស់មនុស្ស ដូច្នេះត្រូវសួរ៖ «ប្រសិនបើអ្នកជំនាញម្នាក់ទៀតផ្ដល់ទម្ងន់ខុសបន្តិច ទីតាំងល្អនៅតែល្អឬទេ?» វិធីសាមញ្ញ៖ ប្ដូរទម្ងន់នីមួយៗ ±២០% (ហើយធ្វើឲ្យផលបូកនៅ ១) ហើយវាស់ភាគរយនៃទីតាំងល្អបំផុត ១០% ដែលនៅដដែល៖

```javascript
function top10(img) {
  var p90 = img.reduceRegion({reducer: ee.Reducer.percentile([90]), geometry: aoi.geometry(), scale: 90, maxPixels: 1e9}).values().get(0);
  return img.gte(ee.Number(p90));
}
```

ទីតាំងដែលស្ថិតក្នុងក្រុមល្អបំផុត ក្នុងគ្រប់សេណារីយ៉ូ គឺជាការណែនាំដែលរឹងមាំជាងគេ។

### ១៣.៣.៧. ពីផែនទី ទៅទីតាំងបេក្ខភាព

<figure markdown>
--8<-- "assets/svg/agv/a13-candidates.svg"
<figcaption>រូបទី១៣.៧៖ ផែនទីជួយតម្រង មិនមែនសម្រេច។</figcaption>
</figure>

!!! note "អានរូបនេះ"
    - connectedPixelCount() និង reduceToVectors() បម្លែងក្រឡាល្អ ទៅជាតំបន់បេក្ខភាពដែលមានផ្ទៃ។
    - ដកតំបន់តូចពេក ហើយតម្រៀបតាមផ្ទៃ និងពិន្ទុ។
    - ទីតាំងបេក្ខភាពត្រូវតែពិនិត្យនៅវាល ហើយពិភាក្សាជាមួយសហគមន៍ និងអាជ្ញាធរ មុនសម្រេច។


```javascript
var best = suit.gte(0.75).selfMask();
var big = best.updateMask(best.connectedPixelCount(100, true).gte(20));           // ≥ ២០ ក្រឡា (~១,៨ ហិកតា)
var sites = big.reduceToVectors({geometry: aoi.geometry(), scale: 30, geometryType: 'polygon', maxPixels: 1e10, tileScale: 4})
  .map(function(f) {
    var m = suit.reduceRegion({reducer: ee.Reducer.mean(), geometry: f.geometry(), scale: 30}).get('S');
    return f.set({area_ha: f.geometry().area(10).divide(1e4), score: m});
  }).sort('score', false).limit(40);
Export.table.toDrive({collection: sites, description: 'pond_candidates', folder: 'applied_gis', fileFormat: 'KML'});
```

ផែនទីភាពសមស្រប **តម្រង** ជម្រើស ហើយកាត់បន្ថយការចុះវាល៖ វាមិនសម្រេចជំនួសមនុស្សទេ។ កម្មសិទ្ធិដី ការយល់ព្រមរបស់សហគមន៍ និងលក្ខខណ្ឌនៅនឹងកន្លែង មិនមាននៅក្នុងទិន្នន័យផ្កាយរណបទេ។

### ជំហានទី២៖ ទម្ងន់ និងឧបសគ្គ

ប្រើទម្ងន់ AHP (ផ្នែក ១៣.៣.៤) និងឧបសគ្គ (ផ្នែក ១៣.៣.៥)។ គណនាភាគរយនៃខេត្តដែលនៅសល់ក្រោយឧបសគ្គ។

### ជំហានទី៣៖ ភាពរសើប

គណនាផែនទីបី៖ ទម្ងន់ AHP ទម្ងន់ស្មើ (២៥% ម្នាក់) និងទម្ងន់ចំណាត់ថ្នាក់ (៤០ ៣០ ២០ ១០)។ រកក្រឡាដែលស្ថិតក្នុង top10 ទាំងបី៖ `top10(sA).and(top10(sB)).and(top10(sC))`។

### ជំហានទី៤៖ ទីតាំងបេក្ខភាព

បម្លែងក្រឡារឹងមាំទៅជាពហុកោណ (ផ្នែក ១៣.៣.៧) តម្រៀបតាមពិន្ទុ ហើយនាំចេញ ៤០ ទីតាំងជា KML សម្រាប់ Google Earth និងកម្មវិធីទូរស័ព្ទចុះវាល។

## ១៣.៥. សកម្មភាពអនុវត្ត

## ១៣.៦. ការយល់ច្រឡំដែលត្រូវប្រុងប្រយ័ត្ន

**១. «ផែនទីភាពសមស្រប ជាចម្លើយចុងក្រោយ»**
វាជាឧបករណ៍តម្រង និងពិភាក្សា។ ការសម្រេចត្រូវការការពិនិត្យវាល និងការចូលរួមពីអ្នកពាក់ព័ន្ធ។

**២. «អាចបូកស្រទាប់ដើមបានដោយផ្ទាល់»**
ដឺក្រេ និងមីលីម៉ែត្រ មិនអាចបូកគ្នាបានទេ។ ត្រូវធ្វើស្តង់ដារមុន ហើយពិនិត្យទិស (តិចល្អ ឬច្រើនល្អ)។

**៣. «ទម្ងន់ AHP ជាការពិតវិទ្យាសាស្ត្រ»**
AHP ធ្វើឲ្យការវិនិច្ឆ័យមានរចនាសម្ព័ន្ធ និងស៊ីសង្វាក់ ប៉ុន្តែវានៅតែជាការវិនិច្ឆ័យ។ ការវិភាគភាពរសើបចាំបាច់។

**៤. «លក្ខខណ្ឌទាំងអស់ត្រូវជាកត្តា»**
លក្ខខណ្ឌដែលមិនអាចទូទាត់បាន (តំបន់ការពារ ទឹក) ត្រូវជាឧបសគ្គ ដើម្បីកុំឲ្យពិន្ទុល្អផ្សេងទៀតទូទាត់វា។

**៥. «ក្រឡាដែលមានពិន្ទុខ្ពស់បំផុតតែមួយ ជាទីតាំងល្អបំផុត»**
ក្រឡាតែមួយអាចជាសំឡេងរំខាន។ ជ្រើសក្រុមក្រឡាដែលមានផ្ទៃគ្រប់គ្រាន់ និងរឹងមាំក្នុងសេណារីយ៉ូច្រើន។

## ១៣.៧. សេចក្ដីសង្ខេបមេរៀន

MCDA បម្លែងសំណួរទីតាំងទៅជាកត្តា (អាចទូទាត់) និងឧបសគ្គ (បាទ/ទេ)។ កត្តាត្រូវបានធ្វើស្តង់ដារទៅ ០–១ ដោយ unitScale ឬមុខងារ fuzzy តាមទិសត្រឹមត្រូវ ហើយទម្ងន់មកពីចំណាត់ថ្នាក់ ឬ AHP ជាមួយ CR < ០,១។ WLC បូកកត្តាមានទម្ងន់ ហើយឧបសគ្គ mask ក្រឡាដែលមិនអាចប្រើ។

ការវិភាគភាពរសើបពិនិត្យថាទីតាំងល្អរឹងមាំចំពោះការប្ដូរទម្ងន់ ហើយ connectedPixelCount និង reduceToVectors បម្លែងក្រឡាល្អទៅជាទីតាំងបេក្ខភាព សម្រាប់ការចុះវាល និងការពិគ្រោះយោបល់។

!!! abstract "គំនិតស្នូលនៃមេរៀន"
    MCDA ធ្វើឲ្យការសម្រេចចិត្តមានតម្លាភាព៖ គ្រប់ការជ្រើស (លក្ខខណ្ឌ ចំណុចបត់ ទម្ងន់) ត្រូវបានសរសេរ និងអាចពិភាក្សាបាន។ តម្លៃរបស់វាមិនស្ថិតនៅលើផែនទីចុងក្រោយតែមួយទេ ប៉ុន្តែស្ថិតលើការសន្ទនាដែលវាបង្កើត។

សំណួរនេះនាំទៅ **មេរៀនទី១៤៖ កម្មវិធី Earth Engine និងផែនទីវេប**។
